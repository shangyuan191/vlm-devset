## 1. 名詞小字典
| 名詞 | 白話意思 |
|---|---|
| S1 / S2 | 情境一：只要求「同風格」；情境二：要求「同風格 + 同品項」。兩個情境用同一批 query 圖 |
| 合格候選 | 40 件候選中真的符合限制的 12 件 |
| Align@5 | 模型挑的 5 件中，合格的比例 |
| Div@5 | 只看挑中的合格商品，各個「自由維度」（顏色、材質、形狀…）有多不同；合格少於 2 件的題不算 |
| EffCov@5 | 主要指標：自由維度的覆蓋率，沒挑到合格商品就是 0，滿分 1。它同時要求「對」和「多樣」 |
| 自由維度 | 合格候選中這個屬性有 ≥ 2 種值（例如顏色有 4 種），才拿來要求多樣 |
| Oracle | 事先知道答案時能拿到的最高分（每題都 1.00） |
| img / style_given | img：只給圖；style_given：額外告訴模型「參考商品的風格是 X」（X 是它自己在風格判斷題的答案） |
| Style Acc | 只給 query 圖，模型能不能選對風格 |
| 順序 o0/o1/o2 | 候選的排列順序（原順序 + 兩種打亂），用來看模型是否受位置影響 |
| 困難干擾 | 看起來很像答案、但其實不合格的候選（例如同品項但別的風格），用來考模型會不會被騙 |
| SigLIP2 top-5 | 不用大模型：用圖片向量找和參考圖最像的 5 件。純看圖，公平的對照組 |
| SigLIP2 + 輪流 MMR（siglip2-mmr-free）† | 先用 SigLIP2 取最像的 10 件，再**依標註答案的屬性**（顏色 / 材質 / 形狀 / 品項）輪流挑不同值。**它看得到標註答案，模型看不到**，所以是「半作弊」的參考值，不是公平對手（Opus 審查補註） |
| SigLIP2 + 標準 MMR（siglip2-mmr-std） | 只用圖片向量：挑和參考圖像、又和已選的不像的（λ = 0.7）。不看標註，公平 |
| H5 | 假設：模型「認得出風格，但選品時沒用上」。比較 style_given 和 img 的差 |
| H2 | 假設：S1（可以換品項）時，模型在顏色 / 材質 / 形狀上變化得比 S2 少。表中是同一張 query 的 S1 − S2 |
| H3 SameCat@5 | 只看 S1：挑出的 5 件中和參考圖同品項的比例。越高代表越「黏」在參考圖的品項上，不敢換品項 |
| H6 Dup@5 | 5 件中「顏色、材質、形狀三樣都一樣」的配對數，越高代表挑到越多近似重複款 |
| 95% CI | 用 bootstrap（重抽題目 10,000 次）估的誤差範圍；範圍跨過 0 就代表「看不出差別」 |
| 位置偏誤 | 模型是否偏愛排在前面的候選；完全隨機時「選到第 1 位」約 5/40 = 0.125 |

## 2. 補標緩衝（A 節）
- **為什麼**：有幾格剛好湊滿，出題時沒餘裕；industrial × chair 可當 query 的單一商品圖太少。
- **怎麼做**：沿用階段 2 的腳本，Claude 補標第 5 輪（162 件），本地兩位標註者標完，再補標單一商品欄位；Claude 階段 3 花費不到上限 $5。
- **結果**：
  - mid_century|lamp：合格 30 / 目標 26
  - coastal|table：合格 32 / 目標 26
  - farmhouse_rustic|chandelier_pendant：合格 33 / 目標 26
  - mid_century|wall_art：合格 20 / 目標 13
  - industrial|chair：合格 67 / 目標 26
- **代表什麼**：每格都有足夠合格商品做 12 件合格候選與 query。

## 3. 出題（B 節）
- 每格最多 5 個 query；實際：boho|lamp 3 以外每格 5 個。
- 候選 40 件 = 合格 12 + 困難干擾 12 + 困難干擾 8 + 隨機 8。有 71 題換 seed 重抽過（多半是 Oracle EffCov 不到 1）。
- 自由維度個數 |F|（題數）：S1：4 個維度 108 題；S2：2 個維度 24 題, 3 個維度 84 題
- 標題都用「去風格字」版本（`c1_stats.STYLE_REGEX` 全部 pattern）。細節見 `DECISIONS.md` 3–6。

## 4. 跑模型（C 節）
每個模型 108 個風格判斷 + 216 題 × 3 順序 × 2 條件（img、style_given）。Random 期望值每題蒙地卡羅 1000 次；SigLIP2 用 CPU（top-5、輪流 MMR、標準 MMR λ=0.7）。

## 6. 限制
- **query 圖的風格沒有人工確認**：只靠三方一致 + Claude 高信心（style_conf = 3）。
- **題數小**：108 個 query、216 題，每個模型每格只有幾題；CI 很寬，差異要小心解讀。
- **③ 的規則（自由維度 n_d ≥ 2）教授尚未確認**，Skyler 決定先用它做 dev set。
- **為了塞進 16384 tokens 偏離 RUNBOOK**：Qwen 系列 `max_pixels` 由 409600 降為 307200（41 張圖在 409600 下 prompt 約 16380 tokens，加輸出會超過）；LLaVA-OV2 送出的圖縮到長邊 560（900 時 41 張約 32k tokens）。所以這兩類模型看到的圖比其他模型小，和 11-16 的結果不能直接比。
- boho × lamp 只有 3 個合格 query；wall art 格只出現在 S1。
- 近似重複圖只用 `phash_dups.json`，沒有重算。
- **（Opus 審查補充）gemma4-12b 和 qwen38-27b 同時是標註者和受測模型**：query 圖的條件是「三位標註者（Claude、Qwen3.8-27B、Gemma4-12B）都標同一風格」，合格商品也要它們之一同意。所以這兩個模型的 Style Acc 和選品分數可能偏高（有點像考自己出的題），和其他 5 個模型比較時要打折。
- **（Opus 審查補充）siglip2-mmr-free 看得到標註屬性**（名詞小字典 †）。它的 S2 EffCov 比所有模型都高，但不代表「簡單方法打敗大模型」；公平的純圖片對照是 siglip2-top5 與 siglip2-mmr-std。
- **（Opus 審查補充）標題去風格字不完全**：`STYLE_REGEX` 只刪風格名稱本身。(a) 1 件商品（item_0773，出現在 9 題）原標題是 "Mid Modern Century"，刪掉 Modern 後反而拼出 "Mid Century"；(b) 和風格高度相關、但不是風格名稱的字還在，例如 beach（出現 205 次）、steampunk（116）、country / cottage、barn、antique。所以 S1 的 Align 有一部分可能來自「讀標題」而不是「看圖判斷風格」。
